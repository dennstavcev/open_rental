# 0001. Формат реализации — веб-приложение

Дата: 2026-07-17
Статус: Принято

## Контекст

Проект — сервис для коммуникации между арендодателем и арендатором
помещения. Нужно определить формат реализации на старте, чтобы
дальше строить архитектуру (frontend/backend/данные) под конкретную
платформу.

## Рассмотренные варианты

1. Веб-приложение — доступно с любого устройства через браузер, не
   требует установки, проще для обеих сторон (арендодатель и
   арендатор редко устанавливают отдельные приложения ради одного
   объекта).
2. Мобильное приложение (нативное) — лучше для push-уведомлений и
   офлайн, но дороже в разработке и требует установки с обеих сторон.
3. Документация/план без кода — рассматривался как формат для этой
   стадии, отклонён: продукт нужен как рабочий код.

## Решение

Реализация — веб-приложение (код). Мобильная версия/PWA — возможное
расширение в Phase 3 (`docs/ROADMAP.md`), не блокирует MVP.

## Последствия

- Архитектура (`docs/ARCHITECTURE.md`) строится вокруг веб-стека
  (frontend + backend + БД), а не нативного мобильного SDK.
- Push-уведомления в MVP не гарантированы — на старте email/websocket.
- Выбор конкретного фреймворка/языка — отдельный будущий ADR.
