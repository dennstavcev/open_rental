# 0023. Полный визуальный редизайн — Tailwind + shadcn/ui, источник макетов Stitch

Дата: 2026-08-20
Статус: Принято

## Контекст

Текущий визуал вырос из Claude Design handoff (2026-07-23) и зафиксирован
в `docs/DESIGN_SYSTEM.md` со статусом «утверждена». За это время фронт
дорос до 19 экранов (`frontend/app/**/page.tsx`, ~4060 строк tsx) при
всего 4 компонентах в `frontend/components/` (~660 строк) и одном файле
стилей `frontend/app/globals.css` — 1544 строки, ~159 классов.

Владелец продукта поставил задачу: не точечная полировка, а визуально
вылизанный продукт, ради которого допустима глобальная переработка
фронта.

Ограничения и факты, которые эту задачу формируют:

- **Разметка расползлась по страницам.** 4060 строк в `app/` против 660 в
  `components/` — самые тяжёлые файлы `leases/[id]/page.tsx` (493),
  `onboarding/page.tsx` (447), `bills/page.tsx` (368),
  `party-info/page.tsx` (354). Общие блоки продублированы, единая правка
  дизайна требует обхода всех экранов вручную.
- **Десктопа фактически нет.** В `globals.css` четыре медиазапроса; на
  широком экране это мобильный макет по центру. Для арендодателя с
  несколькими объектами (Фаза 12, «портфель») это заметный минус.
- **Примитивы написаны руками.** `Sheet`, `Segmented`, `LeaseTabs` в
  `components/ui.tsx` выглядят нормально, но фокус-трап, клавиатура и
  aria в них неполные.
- **Фронтовых тестов ноль.** CI (`.github/workflows/ci.yml`) гоняет для
  фронта только `npm run build`. Единственная страховка — живая проверка
  по сценарию из этого файла (throwaway-аккаунты через API + токены в
  `localStorage`).
- **Инструмент дизайна сменился.** У владельца продукта подключён MCP
  Stitch (в среде WSL). Stitch отдаёт разметку в tailwind-идиоме.
- **Фазы 5–12 почти все тянут за собой фронт**: Фаза 5 — редизайн экрана
  истории показаний, Фаза 10 — таймлайн на `/properties/[id]`, Фаза 11 —
  целая новая поверхность (график дохода + калькулятор со слайдером),
  Фаза 12 — портфельный вид `/reports`.

## Рассмотренные варианты

1. **Точечная полировка на текущем CSS.** Дёшево и обратимо, ничего не
   ломает. Отклонено: не решает ни расползшуюся разметку, ни отсутствие
   десктопа, ни примитивы — то есть не даёт заявленного результата, а
   размазывает работу по всем будущим фазам.
2. **Stitch как генератор макетов, перенос вручную в текущий
   `globals.css`.** Сохраняет кодовую базу, `lib/*` не трогается,
   дизайн-система остаётся своей. Отклонено по одной причине — **цена
   итерации**. Каждый круг «поправили в Stitch → перенесли в код»
   становится ручным переводом из tailwind-идиомы в классы. На практике
   это означает один круг вместо пяти, а вылизанность берётся из пяти.
3. **Полный переезд: Tailwind + слой токенов + примитивы shadcn/ui,
   Stitch — источник истины по дизайну.** Дорого разово, но делает
   круг итерации дешёвым и закрывает разметку, десктоп и доступность
   одним заходом.

## Решение

Принят вариант 3.

- **Tailwind CSS 3.4** (не v4 — связка с Next 14.2 у v3.4 проверенная,
  переход на v4 отдельным решением, когда/если поедет Next 15).
- **Токены остаются CSS custom properties.** Tailwind-тема ссылается на
  переменные, а не дублирует значения хардкодом. Палитра, типографика и
  тон — как определит новая дизайн-система (см. ниже), но механизм
  «семантические алиасы поверх сырых токенов» из текущего `globals.css`
  сохраняется: он себя оправдал.
- **shadcn/ui — только примитивы** (диалог, селект, табы, тосты, формы),
  копируются в `frontend/components/ui/` и перекрашиваются под тему.
  Это не UI-кит целиком: продуктовые компоненты (`Row`, `PageHeader`,
  `LeaseTabs`, `EmptyState`) остаются своими, переписанными поверх
  примитивов.
- **Источник истины по дизайну — проект в Stitch.** Направление
  правок: Stitch → код. Правка визуала, начатая прямо в коде мимо
  Stitch, считается расхождением и подлежит возврату в Stitch.
  `docs/DESIGN_SYSTEM.md` **переписывается** из нового Stitch-проекта;
  Claude Design handoff (2026-07-23) переводится в историческую справку.
- **Макеты обязаны покрывать состояния**, а не только happy path: пусто,
  загрузка, ошибка, просрочено, «ждём вторую сторону». Состояние, не
  нарисованное в Stitch, доделывается на глаз в коде — именно там
  теряется полировка.
- **Десктопная сетка входит в скоуп.** Не «мобильный макет по центру».
- **Инвариант: `frontend/lib/*` не трогается.** 17 модулей (api, auth,
  billing, chat, leases, …) — контракт с backend. Правка в `lib/` в
  рамках редизайна — сигнал, что что-то пошло не так; такие места
  выносятся в отдельную задачу, а не чинятся по ходу.
- **Порядок работ: редизайн идёт ДО Фаз 5–12, а не после.** Иначе
  каждый новый экран этих фаз верстается дважды — сначала в старой
  системе, потом портируется в новую.
- **Ветка `redesign/stitch`**, мержится в `main` целиком после сквозной
  живой проверки. Длинная параллельная ветка с фронтовыми фазами
  запрещена — конфликты в одних и тех же `page.tsx` гарантированы.
- **Все npm-команды выполняются на стороне Windows.** В
  `frontend/node_modules` лежит `@next/swc-win32-x64-msvc`; `npm install`
  из WSL подменит нативные бинарники на linux-овые и сломает запуск на
  Windows. Сессия в WSL правит только исходники.

## Последствия

**Что становится проще.** Круг итерации дизайна — минуты вместо часа.
Фазы 5–12 строятся сразу в готовой дизайн-системе; Фаза 11 (самая
дизайнерская) получает нормальный визуальный язык, а не «как получится».
Единая правка темы применяется ко всем экранам разом.

**Что становится сложнее.** Появляется build-зависимость Tailwind
(покрыта существующим `npm run build` в CI). Дизайн живёт во внешнем
инструменте — расхождение Stitch ↔ код становится новым классом
проблем, лечится только дисциплиной направления правок.

**Что меняется в документации и ролях.**

- `docs/DESIGN_SYSTEM.md` — переписывается из Stitch-проекта, старая
  редакция уходит в историю (`docs/CHANGELOG.md`).
- `.claude/agents/designer.md` — источник дизайна меняется с MCP
  `claude_design` на MCP Stitch; правило «референс — отправная точка, не
  спецификация» остаётся в силе.
- `docs/ROADMAP.md` / `docs/DEV_STATE.md` — редизайн встаёт перед
  Фазой 5.

**Что меняется в планировании.** На время редизайна фронтовые фазы
заморожены. Технически backend можно вести параллельно без пересечений
(`backend/` и `frontend/` — разные деревья, конфликтов в git нет):
безопасны Фазы 8 (структурированный адрес), 9 (акт возврата) и серверная
часть 12 (агрегат по заявкам). Владелец продукта решил этой возможностью
не пользоваться — редизайн выполняется соло и автономно одной сессией,
без параллельных чатов и промежуточных согласований (см.
`docs/DEV_STATE.md`, «Режим работы»). Соответственно на время редизайна
разработка backend приостановлена, а не идёт вторым потоком.

**Чего это решение НЕ отменяет.** ADR-0003 (стек React/Next.js) — Tailwind
дополняет его, а не пересматривает. ADR-0016 (polling), ADR-0021/0022
(ПДн и согласие) — продуктовая логика редизайном не затрагивается,
экраны переносятся с сохранением поведения.

**Риск, принятый осознанно.** Фронтовых тестов нет, поэтому регрессии
ловятся только живой проверкой экран за экраном по сценарию из
`docs/DEV_STATE.md`. Это заложено в объём работ, а не «сверху».
