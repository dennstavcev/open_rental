# 0007. Файловое хранилище — интерфейс абстракции + локальная реализация

Дата: 2026-07-22
Статус: Принято (частично — провайдер и хостинг сознательно не решены)

## Контекст

Каждый модуль MVP работает с файлами: фото объектов, сканы подписанных
договоров, фото показаний счётчиков, квитанции. `docs/ARCHITECTURE.md`
указывал тип ("S3-совместимое хранилище"), но не провайдера. Выбор
конкретного провайдера физически привязан к вопросу хостинга и 152-ФЗ
(локализация ПДн) — эта часть **сознательно не решается сейчас** по
явному указанию: тесты пока идут на localhost, вопросы хостинга и
юридической части закрываются отдельно, позже (см.
`docs/READINESS_AUDIT.md`). Но само программирование не должно
стоять — нужна абстракция, которая работает локально уже сегодня и не
потребует переписывания кода при выборе прод-провайдера.

## Рассмотренные варианты

1. **Жёстко закодировать конкретный облачный SDK (например, AWS S3
   SDK) уже сейчас.** Требует реального аккаунта/ключей, привязывает
   код к конкретному вендору до того, как решён вопрос локализации
   данных — рискует потребовать переделки.
2. **Интерфейс `StorageProvider`** (`put(key, file)`, `get(key)`,
   `delete(key)`, `getUrl(key)`) на уровне приложения + первая
   реализация — **локальная файловая система** (диск контейнера/
   dev-машины, каталог `./uploads`), используемая на localhost и в
   тестах. Любой S3-совместимый провайдер (включая российские —
   Yandex Object Storage, VK Cloud, Selectel — или self-hosted MinIO)
   подключается позже как вторая реализация того же интерфейса, без
   изменений в модулях, которые хранилище используют.

## Решение

Вариант 2. Реализуется `LocalFsStorageProvider` для разработки и
тестов. Продовый провайдер (и вопрос, должен ли он физически находиться
в РФ из-за 152-ФЗ — см. `docs/READINESS_AUDIT.md`, красная зона, п.3)
остаётся открытым и не блокирует Phase 1 на localhost.

## Последствия

- Все модули (Properties, Leases/LeaseDocument, Meter/MeterReading,
  Documents) работают через интерфейс `StorageProvider`, не напрямую с
  диском или конкретным SDK.
- Переключение на прод-провайдера — конфигурация/DI-биндинг, не
  переписывание бизнес-логики.
- `docs/ROADMAP.md`: закрывает возможность начать модули с файлами на
  Phase 1, не дожидаясь решения по хостингу.
- Явно НЕ закрывает: выбор конкретного прод-провайдера, соответствие
  152-ФЗ по месту физического хранения — эти пункты остаются в
  `docs/READINESS_AUDIT.md` как открытые, решаются вместе с хостингом.
