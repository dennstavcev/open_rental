# 0006. Механизм аутентификации — email+пароль, собственный JWT

Дата: 2026-07-22
Статус: Принято

## Контекст

`docs/ARCHITECTURE.md` держал открытым "email+пароль или OAuth" — это
буквально первый модуль Phase 1 (`docs/ROADMAP.md`), откладывать нельзя.
Рынок — физлица в РФ (см. `docs/IDEA.md`), два типа пользователей
(landlord/tenant), приглашение по email как основной механизм
знакомства сторон (`Invitation`, `docs/ARCHITECTURE.md`).

## Рассмотренные варианты

1. **Email + пароль, собственный JWT (access + refresh токены), выпускаемый
   backend'ом.** Не зависит от внешних identity-провайдеров, проще
   тестировать локально (нет внешних callback URL, нет зависимости от
   доступности стороннего сервиса на localhost), полностью под нашим
   контролем с точки зрения хранения/срока жизни сессии.
2. **OAuth через внешних провайдеров (Google/VK ID/Яндекс ID).**
   Удобнее для пользователя (меньше паролей), но требует
   зарегistрированного домена/redirect URI у провайдера — неудобно на
   этапе разработки на localhost, добавляет внешнюю зависимость до
   того, как решён вопрос хостинга (сознательно отложен, см.
   `docs/READINESS_AUDIT.md`). Можно добавить позже как опцию, не
   меняя базовую модель пользователя.

## Решение

Email + пароль (хеш — bcrypt/argon2) как основной и единственный
механизм в MVP. Backend выпускает собственный JWT (access, короткий TTL)
+ refresh-токен (более длинный TTL, хранится с возможностью отзыва).
OAuth (VK ID/Яндекс ID) — кандидат на Phase 2+ как дополнительный способ
входа, не замена.

## Последствия

- Модуль Auth (`docs/ROADMAP.md`, Phase 1, первый пункт) можно начинать
  без внешних зависимостей — подтверждено, что подходит для
  разработки/тестов на localhost.
- Верификация email при регистрации — техническая деталь реализации
  (не отдельный ADR), но нужен email-провайдер уже здесь; для дев/теста
  на localhost используется локальная заглушка (см. обновление
  `docs/ARCHITECTURE.md`, компонент Notifications) — реальный
  production-провайдер решается вместе с хостингом, не сейчас.
- `docs/ARCHITECTURE.md`, «Открытые архитектурные вопросы»/стек: строка
  "Аутентификация" перестаёт быть "или", фиксируется однозначно.
