# 0018. Акт приёма-передачи имущества как Приложение №1 к договору

Дата: 2026-08-19
Статус: Принято

## Контекст

ADR-0017 убрал из генерируемого договора все персональные данные сторон
(ФИО, паспорт, адрес, телефон) — эти поля остаются прочерками. Продуктовая
задача: компенсировать эту «пустоту» тем, что можно оцифровать без
персданных и что реально нужно обеим сторонам — точной описью имущества,
передаваемого вместе с помещением (техника, мебель), оформленной как
приложение к договору.

## Рассмотренные варианты

1. **Просто текстовое поле в `Lease` со свободным описанием имущества.**
   Отклонено: не структурировано, нельзя показать таблицей в документе,
   нельзя редактировать позиции по одной.
2. **Отдельная сущность `LeaseInventoryItem` (позиция описи: тип техники,
   бренд, модель, количество) + отдельный шаблон-приложение, версионируемый
   как второй `kind` в `LeaseDocument`.** Выбран.
3. **Совсем новая модель документов вместо расширения `LeaseDocument`.**
   Отклонено: `LeaseDocument` уже даёт версионирование, print-ready HTML,
   доступ обеим сторонам — дублировать эту инфраструктуру ради второго
   документа избыточно; достаточно различать «какой это документ» полем.

## Решение

- `LeaseInventoryItem` — новая модель: `leaseId`, `type` (тип техники/
  предмета, свободный текст, обязательно), `brand`/`model` (опционально —
  не у всякого предмета есть бренд), `quantity` (по умолчанию 1). Без
  персональных данных, привязана к `Lease`, не к `User`.
  `leases/:leaseId/inventory-items` (`CRUD`, кроме `GET`) — редактирует
  только landlord, пока `Lease.status = draft` (та же граница, что и у
  остальных полей договора, переиспользует `LeasesService.getOwnedDraft`,
  сделан публичным для этого). Список (`GET`) доступен обеим сторонам —
  через `LeasesService.getForUser`.
- `LeaseDocument` получает поле `kind` (`contract` | `handover_act`,
  default `contract`) — версионируется отдельно на каждый `kind`
  (`@@unique([leaseId, kind, version])`). Не заводили отдельную таблицу
  документов — `LeaseDocument` уже даёт нужную инфраструктуру (версии,
  print-ready HTML, доступ сторон), не хватало только различать вид.
- Новый шаблон `lease-handover-act.template.ts` — «Приложение №1... Акт
  приёма-передачи имущества»: таблица позиций (тип/бренд/модель/кол-во),
  подписи без имён (`Арендодатель:` / `Арендатор:`, только прочерк для
  подписи) — согласовано с ADR-0017.
- `LeaseDocumentsService.generateHandoverAct`/`getLatestHandoverAct` —
  параллельно `generate`/`getLatest`, тот же landlord-only на генерацию,
  обе стороны на чтение. Эндпоинты —
  `POST|GET /leases/:leaseId/document/handover-act` (+ `/html`).

## Последствия

- Миграция Prisma: новая таблица `lease_inventory_items`, новое поле
  `kind` на `lease_documents` + смена уникального индекса
  (`leaseId+version` → `leaseId+kind+version`). Применена локально
  (`20260819154145_lease_inventory_and_document_kind`).
- Фронтенд: нужен шаг «Опишите передаваемое имущество» в мастере
  составления договора (позиция за позицией, пока договор — черновик) —
  отдельный инкремент, не входит в этот ADR (только backend).
- Обновляет `docs/ROADMAP.md` (модуль договоров) и `docs/MVP_SCOPE.md`
  (список документов, см. также правку 8.1 в `PRODUCT_QUESTIONS.md` при
  ADR-0017).
- Не меняет флоу активации договора (`LeaseSignedScan`) — акт подписывается
  и сканируется той же физической процедурой, отдельно от него, не
  блокирует переход `sent → active`.
