## 1. Core Identity

- **Project Name**: SoftRent
- **Stitch Project ID**: 9694110487873573027
- **Mission**: коммуникационно-биллинговый слой поверх уже существующих
  отношений аренды между арендодателем и арендатором физлицом в РФ —
  договор, коммуналка по показаниям счётчиков, счета, заявки на
  обслуживание, чат, отчёты. Не маркетплейс, не сервис подбора
  недвижимости.
- **Target Audience**: физлица-собственники 1–20 объектов (landlord) и
  их арендаторы (tenant), рынок РФ. ~90% использования — с телефона
  (фото показаний счётчиков), десктоп — вторичный сценарий у
  собственника с несколькими объектами.
- **Voice**: тёплый, спокойный, премиальный лайфстайл-тон. Не
  формально-юридический, не игривый. Обращение на «вы». Короткие
  императивы на кнопках («Войти», «Сохранить»), без восклицательных
  знаков. Заголовки — человеческие, не корпоративные («Войдите в личный
  кабинет», не «Авторизация пользователя»). Эмодзи не используются
  нигде. Интонация «уютный дом», а не банковское приложение.

## 2. Visual Language

- **Vibe (главное → второстепенное → третье)**: тёплый жилой лайфстайл
  → бытовой финансовый инструмент (данные — сумма/срок/просрочка — самое
  заметное) → сдержанная премиальность через типографику и воздух, не
  через декор.
- **Явно НЕ**: корпоративный SaaS-дашборд, синяя корпоративная палитра,
  равномерная сетка одинаковых карточек, стоковые иллюстрации,
  декоративная анимация.
- **Цвет**: тёплая нейтральная база (кремовый/песочный → терракотовый →
  холодный серо-голубой низ, наследие текущей палитры) + ровно один
  холодный акцент (фиолетовый) — только на первичных CTA и ссылках,
  нигде на иконках/статусах/декоре.
- **Типографика несёт основную нагрузку**: одна гарнитура с полной
  кириллицей, жёсткая шкала размеров, крупные заголовки, мера строки
  60–75 символов.
- **Плотность адаптивна**: мобильный — карточки-строки; десктоп —
  настоящие таблицы и многоколоночные раскладки (сейчас этого нет,
  главный дефект текущей версии).
- **Движение** — только функциональное (скелетоны, переходы состояний),
  без декоративной анимации.
- **Иконки** — один комплект, `lucide-react`, никаких самописных SVG
  вперемешку.

## 3. Architecture & File Structure (только для процесса Stitch → код)

- Источник разметки — Stitch-проект (id выше), экспортируется в
  tailwind-идиоме.
- Перенос в код (R2–R3): `frontend/tailwind.config.ts` (тема поверх CSS
  custom properties `frontend/app/globals.css`) → примитивы
  `frontend/components/ui/*` (shadcn/ui, скопированы руками) →
  продуктовые компоненты `frontend/components/*` → экраны
  `frontend/app/**/page.tsx`.
- `frontend/lib/*` — контракт с backend, Stitch/редизайн не касается.
- Направление правок: **Stitch → код**, не наоборот.

## 6. Creative Freedom Guidelines

- Решения по направлению дизайна принимает исполняющая сессия
  единолично, по критериям `docs/REDESIGN_BRIEF.md` → «Направление
  дизайна» — без промежуточных согласований с владельцем продукта.
- Продуктовое поведение и тексты интерфейса — не редизайн-объект,
  переносятся 1:1 (тон уже утверждён, `docs/DESIGN_SYSTEM.md` «Тон и
  стиль текста»).
- Референс (текущая версия приложения, загруженная в Stitch) — отправная
  точка, не буквальная спецификация; расхождения решаются в пользу
  `docs/USER_FLOWS.md`/`docs/MVP_SCOPE.md`, по аналогии с прецедентом в
  `docs/DESIGN_SYSTEM.md`.
